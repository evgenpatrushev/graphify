# Graphify Data Flow — a worked, concrete trace

`ARCHITECTURE.md` gives the contract and `docs/CODE_GUIDE.md` is the module
catalog. This doc is the **third leg**: it follows *real data* through the
pipeline using artifacts captured from running graphify **on its own repo**, so
you can see the exact shapes each stage produces — not idealized examples.

Everything below was generated by actually running the tool (June 2026), so the
numbers and JSON are real.

---

## The one-paragraph version

A file goes in; a slugified set of **nodes** (symbols, files, headings) and
**edges** (`calls`, `imports`, `contains`, …) comes out; those per-file
extractions are merged into a single NetworkX **MultiGraph**; the graph is
written to `graphify-out/graph.json` in node-link form; every query/diff/serve
command reads that one file back. No database, no server state.

```
detect()  →  extract_<lang>()  →  build_from_json()  →  [cluster()]  →  to_json()
   │              │                     │                                  │
 files         {nodes,edges}        nx.MultiGraph                     graph.json
                per file            (merged, deduped)               (node-link JSON)
```

---

## Stage 1 — `detect()` decides what's in scope

`detect.detect(root)` walks the tree and classifies each file. On the graphify
repo it found **254 extractable files**. `classify_file()` tags each as `code`,
`document`, or media, and routes office formats (PDF/DOCX/XLSX) through markdown
converters first.

The output is a manifest; the file-type split that ends up in the graph looks
like this (from the real build):

```
file_type distribution: {'code': 3039, 'rationale': 1269, 'concept': 3, 'document': 1214}
```

Takeaway: this repo is **markdown-heavy** (skill files, CHANGELOG, docs), so a
large fraction of nodes are documentation headings, not code symbols.

---

## Stage 2 — `extract_<lang>()` turns one file into nodes + edges

There is **no single `extract()`**. `extract.py` dispatches on file suffix to a
per-language function (`extract_python`, `extract_js`, `extract_java`, …), each
driven by the same `_extract_generic(path, config)` tree-sitter walker.

Running `extract_python(Path("graphify/diff.py"))` returns:

```
diff.py  →  nodes=30  edges=104
```

Every extractor emits the **same schema** (this is the contract `validate.py`
enforces):

```json
{
  "nodes": [
    {"id": "graphify_diff_ripple_impact", "label": "ripple_impact",
     "source_file": "graphify/diff.py", "source_location": "L151"}
  ],
  "edges": [
    {"source": "graphify_diff_ripple_impact", "target": "graphify_diff_load_graph",
     "relation": "calls", "confidence": "EXTRACTED"}
  ]
}
```

### ⚠️ Gotcha #1: extraction fails *silently* without the grammar package

`extract.py` imports a **per-language tree-sitter package** by name
(`tree_sitter_python`, `tree_sitter_javascript`, …) — **not** the
`tree-sitter-language-pack` umbrella. If that package is missing,
`_extract_generic` returns `{"nodes": [], "edges": [], "error": "... not
installed"}` and the file contributes **zero nodes** — but the overall build
still prints "success."

Concretely: a first build of this repo with only `tree-sitter` installed
produced **1305 nodes with 0 Python symbols** — the entire `.py` codebase was
invisible. After `pip install tree_sitter_python tree_sitter_javascript` and a
rebuild: **5525 nodes, 12190 edges, 4212 Python nodes.** Always sanity-check the
Python-node count after a build.

---

## Stage 3 — `build_from_json()` merges into one graph

`build.build_from_json(extraction)` validates, dedupes by node `id`, and merges
every per-file extraction into a single graph. Node IDs are **slugified**, not
file paths — e.g. the heading "`diff.py` — what changed + blast radius" in a doc
becomes `docs_code_guide_diff_py_what_changed_blast_radius`.

The real relation distribution on the merged graph:

```
calls: 3638   contains: 3598   references: 2235   rationale_for: 1269
imports: 745  imports_from: 273  uses: 206  method: 189  inherits: 37
```

### ⚠️ Gotcha #2: the graph is a **MultiGraph**, and `--no-cluster` skews it

Two things to know before you trust query/diff output:

1. `graph.json` loads back as a NetworkX **`MultiGraph`** (parallel typed edges
   between the same two nodes are allowed). This matters for any code that reads
   edge attributes — see Gotcha #3.
2. A build run with `--no-cluster` and **no LLM backend** is AST-only. Without
   the semantic pass, the cheap structural relation `contains` dominates and
   `calls`/`inherits` are sparse. For a graph rich enough to reason about
   *behavior* (not just containment), run the full build with a backend
   (`GEMINI_API_KEY=… graphify .`) or the clustering pass.

---

## Stage 4 — `to_json()` writes the canonical artifact

`export.to_json()` writes node-link JSON to `graphify-out/graph.json`. Its
top-level keys are:

```
['nodes', 'input_tokens', 'output_tokens', 'links']   # edges live under "links"
```

Every downstream command (`query`, `diff`, `snapshot`, `serve`, `affected`)
reads this one file. That's why `diff.load_graph()` does
`json_graph.node_link_graph(raw, edges="links")`.

---

## Stage 5 — reading it back: the git-change-review path

This is the extension area. `graphify diff HEAD~3 HEAD`:

1. `get_changed_files()` — `git diff --name-status` between the refs.
2. `nodes_for_files()` — map each changed file → its graph nodes (matched on the
   `source_file` attribute). On the real run, `__main__.py` mapped to 100+ nodes
   and `extract.py` similarly; only true non-code (`.gitignore`, `pyproject.toml`)
   landed in "no graph nodes."
3. `ripple_impact()` — BFS out from the changed nodes along behavioral relations
   (`calls`, `imports`, `uses`, `inherits`, …) to find the **blast radius**.

### ⚠️ Gotcha #3 (now fixed): ripple impact + MultiGraph

`ripple_impact` originally read `graph.get_edge_data(u, v).get("relation")`. On a
MultiGraph that call returns `{0: {relation: ...}}` — keyed by edge-key — so
`.get("relation")` always missed and **every diff reported "0 impacted nodes,"**
even for a function with 41 callers. Fixed June 2026 via the `_edge_relations()`
helper, which flattens both Graph and MultiGraph edge shapes (and parallel
edges) into a set of relations. Regression tests live in
`tests/test_diff_ripple.py`. After the fix, the same `HEAD~3..HEAD` diff
surfaces **1374 dependent nodes** (614 direct).

## How to reproduce all of this

```bash
pip install tree-sitter tree_sitter_python tree_sitter_javascript networkx
graphify update . --no-cluster          # AST-only build (no API key needed)
python -c "import json,collections as c; g=json.load(open('graphify-out/graph.json')); \
  print(c.Counter(e['relation'] for e in g['links']))"   # inspect relation mix
graphify diff HEAD~3 HEAD --depth 2      # blast radius over the graph
graphify snapshot save                   # baseline for architectural-evolution diffs
```

*Captured from a live run on the graphify fork, June 2026. Re-run the commands
above if the codebase has moved on.*
